# OSU Microbenchmarks

## Purpose and Description
The OSU Microbenchmark collection represents a suite of tests used to measure MPI performance in distributed computing systems. The tests herein include measurements of network latency (Ping Pong test), bandwidth rates across pairs of processes, collective communication tests (All-Reduce and All-to-All), and accelerator-based All-to-All and message rate tests. In addition, we have two bandwidth tests for bandwidth transfer rates across devices (CPU/Accelerator) on a single host.

## Other Requirements
While returned results may use any MPI distribution, we request that at least one returned osu_mbw_mr test result be obtained with OpenMPI to demonstrate OpenMPI functionality. 

## How to build

We require a version of the OSU Micro-Benchmarks >= 7.4. The micro-benchmarks are downloaded from the following webpage: https://mvapich.cse.ohio-state.edu/benchmarks/ - the micro-benchmarks are compiled according to a standard 'configure' 'make' 'make install' pipeline. An example build/configuration script is located in the 'osu-scripts' directory, labelled as 'build.sh'. With a valid MPI distribution installed, the build script should install the micro-benchmarks without any further configuration steps. As the final step, the executables for the required OSU Micro-benchmarks are copied to the current working directory.

## How to run

Example scripts for both standard and accelerated hardwares are provided in the 'osu-scripts' directory, where there are example scripts provided for each OSU Micro-benchmark that is required. Note, these example scripts are formatted for the SLURM Job Scheduler, but this is not a requirement. Run requirements are listed below.

## Run Definitions and Requirements

The tables below detail the required tests. The OSU micro-benchmarks are required to be run from the minimum possible message size to a message size of 65536kb (65mb) in the default 2<sup>n</sup> increments. Each micro-benchmark should be run a minimum of 5 times each and the mean of these results reported. If improved performance is found for a test that uses a different ranking scheme than specified as below, this may be reported under an "optimized" category submission. Additionally, if these tests are run in a co-scheduled environment that contain different hardware types, this must be noted and information provided on the partitioning softwares (such as use of RDT/MPAM/PQOS or equivalent) used in this environment - for any co-scheduled environment, we allow no more than 2 partitions between different hardware types.

### Standard Run Requirements

| Test          | Description                    | Nodes Used | Ranks Used          |
|---------------|--------------------------------|------------|---------------------|
| osu_latency   | Latency (PingPong)             | 2          | 1 Per Node          |
| osu_mbw_mr    | Multi-Bandwidth & Message Rate | 2          | At Least 80% Available Cores Per Node |
| osu_allreduce | All-Reduce MPI Operations      | All        | At Least 80% Available Cores Per Node |
| osu_alltoall  | All-To-All MPI Operations      | All        | 1 Per NIC            |
| osu_bibw      | Bidirectional Bandwidth Transfer - CPU       | 1          | 2                    |

### Accelerated Run Requirements

A successful run of the OSU Micro-benchmarks on accelerator enabled hardware is defined as a run of the following two tests (alltoall, osu-mbw-mr) executed as a device-to-device test.

| Test          | Description                    | Nodes Used | Ranks Used        |
|---------------|--------------------------------|------------|-------------------|
| osu_mbw_mr    | Multi-Bandwidth & Message Rate | 2          | 1 Per Accelerator |
| osu_alltoall  | All-To-All MPI Operations      | All        | 1 Per Accelerator |
| osu_bibw      | Bandwidth Transfer - Accelerator| 1          | 1 Accelerator    |



## Benchmark data/results to return

When the results from a given test are output, a table will be displayed containing the relevant information for the relevant OSU benchmark. Latency (Ping Pong), All-Reduce, and All-To-All will return latency information associated with the given operations, the Multi-bandwidth/message rate test will return a table that contains both the bandwidth and number of messages successfully sent at a given message size. The mean of results for each message size for each test should be returned in the associated benchmark reporting spreadsheet, and should come from the same series of runs. In addition, please return all output test files.

Example results generated by the tests are located in the directory 'example-results' and are labelled according to OSU micro-benchmark. 

## Tech Spech Information 

Several OSU tests are used to provide information for the technical requirements for ESIF-HPC-4. These tests are used to provide information about the node-level bandwidth performance, max bidirectional aggregate bandwidth performance, and latency characteristics of Kestrel, the current HPC system at NLR. The tests used for this information are as follows


| Test          | Description                    | Nodes Used | Ranks Used          |
|---------------|--------------------------------|------------|---------------------|
| osu_latency   | Latency (PingPong)             | 2          | 1 Per Node          |
| osu_bandwidth | Bandwidth Transfer - CPU | 2          | 1 Per Node   |
| osu_bibw      | Bidirectional Bandwidth Transfer - CPU       | 2          | 1 Per Node                   |
| osu_mbw_mr    | Multi-Bandwidth & Message Rate | 2          | 96 Ranks Per Node   |
